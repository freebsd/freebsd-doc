== Abstract

[.abstract-title]
The release notes for FreeBSD {releaseCurrent} contain a summary of the changes made to the operating system on the {releaseBranch} development line.
This document lists applicable security advisories and errata issued since the last release as well as significant changes to the ecosystem.

toc::[]

[[intro]]
== Introduction

This document details the changes since FreeBSD {releasePrev}.

For installation instructions, see the link:{handbook}bsdinstall/[Installing FreeBSD] chapter of the FreeBSD Handbook.

For upgrading instructions, see link:../upgrading[FreeBSD {releaseCurrent} Upgrading Instructions].

For information on supported hardware, see the link:../hardware[FreeBSD {releaseCurrent} Hardware Compatibility List]. 

All readers are encouraged to consult the link:../errata[FreeBSD {releaseCurrent} errata] before installation or upgrading.
The errata document contains information discovered late in the release cycle, such as known bugs, security advisories, or documentation corrections.

== Userland

This section covers changes and additions to userland applications, contributed software, and system utilities.

[[userland-packages]]
=== System Packaging Changes

Changes in this section only affect systems installed using base system packages (sometimes called _pkgbase_), supported in FreeBSD 15.0 and later.

On the aarch64, armv7, powerpc64, powerpc64le and riscv64 platforms, the non-functional `FreeBSD-apm` package has been removed.  Any existing package, if installed, should be removed after upgrading.
gitref:b04fa0f8b8c5[repository=src].

On the armv7, powerpc64, powerpc64le and riscv64 platforms, the non-functional `FreeBSD-acpi` package has been removed.  Any existing package, if installed, should be removed after upgrading.
gitref:58c08517ce5d[repository=src].

This release includes experimental support for cross-building base system packages on Linux and macOS hosts.  The man:pkg[8] utility must be manually installed on the build host.
gitref:0851f28403e3[repository=src],
gitref:d2ce6ed7f553[repository=src],
gitref:f8b81bfc76d8[repository=src].

[[userland-config]]
=== Userland Configuration Changes

A new man:rc.conf[5] option, `backlight_enable`, enables saving and restoring the backlight level across reboots via the man:backlight[8] rc.d service. The service is disabled by default to avoid interfering with desktop environments.
gitref:5245187af22b[repository=src].

[[userland-programs]]
=== Userland Application Changes

Deprecated control values have been removed from man:mixer[8]; users relying on these legacy controls must use the current mixer command interface: `on`, `off`, `toggle`, `set`, `add`, `remove` instead of `1`, `0`, `^`, `=`, `+`, `-`.
gitref:5ec4a7bb2cdf[repository=src].
{{< sponsored "The FreeBSD Foundation" >}}

man:makefs[8] now accepts an autotrim option that sets the autotrim property of the created ZFS pool to on or off, allowing imported pools to start trimming freed space without a separate zpool set step. When the option is omitted, the pool retains the default value of off.
gitref:4ff8c71df5de[repository=src].

[[kernel]]
== Kernel

This section covers changes to kernel configurations, system tuning, and system control parameters that are not otherwise categorized.

[[kernel-general]]
=== General Kernel Changes

A new security knob allows unprivileged access to the kernel environment (kenv) to be disabled. When enabled, only privileged processes, including jailed root, can read kernel environment variables, limiting exposure of sensitive information.
gitref:da9d26a215a6[repository=src].

The man:mac_do[4] security module now supports configurable executable paths, allowing up to eight paths to be authorized for credential change requests. This enables thin jail scenarios where man:mdo[1] is not at its canonical path and permits other userland programs to use man:setcred[2]. Configuration is available via the `security.mac.do.exec_paths` sysctl and the `mac.do.exec_paths` jail parameter.
gitref:8cbd56ec1c54[repository=src].
{{< sponsored "Google LLC (GSoC 2025); The FreeBSD Foundation (review, commit)" >}}

[[drivers]]
== Devices and Drivers

This section covers changes and additions to devices and device drivers since {releasePrev}.

[[drivers-device]]
=== Device Drivers

The man:em[4] and man:igb[4] drivers have been reworked for Wake-on-LAN, including corrected wake capability advertisement and programming, per-controller NVM handling, restored receive filters after suspend, and updated man page documentation. Wake from S3 is now supported on additional controllers such as the 82576 and 82574L, while unsupported 82541ER wake is no longer advertised.
gitref:0cab2bc676d7[repository=src].
{{< sponsored "BBOX.io" >}}

The man:igb[4] driver now supports SR-IOV on Intel 82576 and I350 controllers, with up to seven virtual functions (VFs) per physical function (PF).
Enabling SR-IOV requires `options PCI_IOV`, MSI-X, and a single PF transmit/receive queue pair; see man:igb[4] for the required loader tunables.

Virtual functions now use the separate man:igbv[4] driver, which adds Hyper-V support and can provide the accelerated data path for man:hn[4].
On Hyper-V, VFs support an MTU of up to 1500 bytes and host-assigned access VLANs with untagged guest traffic.
Guest VLAN trunks require the synthetic man:hn[4] data path with SR-IOV disabled for the virtual network adapter on the host.

[IMPORTANT]
====
Existing 82576 and I350 VF interfaces are renamed from `igbN` to `igbvN`.
Before booting the upgraded kernel, update VF interface references in man:rc.conf[5], firewall rules, and other network configuration, and change VF device tunables from `dev.igb.N` to `dev.igbv.N`.
Systems with both PFs and VFs should also check PF unit numbers after the driver split.
The drivers remain in [.filename]#if_em.ko#; existing `if_em_load` and `if_igb_load` settings continue to work, and `if_igbv_load` is also supported.
====

gitref:3a0d13751d21[repository=src].
{{< sponsored "BBOX.io" >}}

The man:tpm[4] driver is re-enabled in amd64 GENERIC and MINIMAL kernels and in the MPC85XX and QORIQ64 PowerPC configurations, restoring TPM support and entropy harvesting after suspend/resume fixes for both TPM 1.2 and TPM 2.0.
gitref:7fdc748c0c3d[repository=src].
{{< sponsored "BBOX.io" >}}

The man:ixgbe[4] driver has received numerous SR-IOV improvements. SR-IOV is now enabled on E610 physical functions (up to 63 virtual functions), and malicious-driver detection with per-pool recovery is supported on X550-family adapters (including X552/X553), with VF traffic held disabled until the reset handshake completes. VFs now support up to three secondary unicast MAC filters, honor the allow-promisc IOV property for multicast and promiscuous modes, and correctly preserve VLAN ownership and per-VF isolation (including delivery of PF-assigned port VLAN traffic to VFs as untagged). Anti-spoofing policy for VF MAC/VLAN is enforced, protecting LLDP and flow-control Ethertypes, with per-VF spoof-event accounting.
gitref:34208cb35076[repository=src],
gitref:ad9149c3aabe[repository=src],
gitref:626a367c2b72[repository=src],
gitref:1ff14169af4b[repository=src],
gitref:06a514be60c8[repository=src],
gitref:59bd5fc94c54[repository=src].
{{< sponsored "Dirk-Willem van Gulik from Web Weaving (E610 hardware); BBOX.io" >}}

The man:ixgbe[4] driver now recognizes 10GBase-BX BiDi SFP+ optical modules and reports their link speed and reach correctly, enabling single-strand single-mode 10 Gb/s links on supported Intel adapters.
gitref:7316de430095[repository=src].

The man:ixl[4] driver now enforces SR-IOV virtual function VLAN policies, with access VFs restricted to a hardware PVID and trunk VFs limited to 16 VLANs (VLAN 0 implicitly admitted). Hardware VLAN anti-spoofing and untrusted-VF limits of 18 MAC addresses and 16 VLANs are applied, and the effective policy is reported through the VF status interface and documented in ixl(4).
gitref:3be664785727[repository=src].

The man:ixgbe[4] driver now isolates a virtual function whose guest driver repeatedly causes transmit failures after a reset, preventing one faulty guest from leaving an 82599 or X540 physical function unusable for other guests. This keeps the physical port available to all other guests on the same adapter.
gitref:de91b2a0c393[repository=src].

The man:ntsync[4] driver provides kernel-level support for Windows NT synchronization primitives via a `/dev/ntsync` device compatible with the Linux interface used by Wine and Proton. This allows Wine-based applications and games to perform thread synchronization in the kernel instead of user space, reducing overhead and improving performance and stability for multi-threaded Windows software on FreeBSD.
gitref:43702cfc0ccb[repository=src].

man:nullfs[4] now permits mounting a VSOCK file directly on top of another socket, allowing containerized processes to share man:unix[4] sockets without exposing an entire directory. The change improves secure socket sharing for container workflows.

[[boot]]
== Boot Loader Changes

This section covers the boot loader, boot menu, and other boot-related changes.

[[boot-loader]]
=== Boot Loader Changes

The UEFI boot loader now applies command-line overrides earlier, so console selection via man:efibootmgr[8] takes effect before the GELI passphrase prompt. This provides serial console access on systems that do not advertise a serial console through ConOut.
gitref:ea041ed323ee[repository=src].

man:bhyveload[8] now releases its host /boot handle before executing guest boot scripts, limiting the sandbox's exposure to the host /boot directory.
gitref:84ec2d3b67df[repository=src].

The boot loader now rejects ELF files with inconsistent segment sizes (where a segment's file size exceeds its in-memory size), preventing malformed kernels from being loaded. Normal boot is unaffected.
gitref:6e4ef01c603c[repository=src].

The man:boot0cfg[8] utility now accepts a regular file as its trailing argument, not just a live disk provider. This allows users to configure man:boot0[8] parameters in a binary before flashing it with man:gpart[8] bootcode or using it with man:mkimg[1].
gitref:15a0a7d525cf[repository=src].

The EFI loader now allocates trampoline memory as executable code rather than data, so firmware that enforces non-executable data protections can boot it successfully. The trampoline is the small stub that hands control from the loader over to the kernel. This improves boot reliability on affected systems.
gitref:6db7fa3765ae[repository=src].
{{< sponsored "The FreeBSD Foundation" >}}

The boot loader now recognizes ELF constructor sections and passes them to the kernel, allowing constructors to run during boot. This is required for KASAN.
gitref:984a3970b16f[repository=src].
{{< sponsored "The FreeBSD Foundation" >}}

The boot loader's graphical menu no longer suffers from display corruption caused by incorrect shadow buffer offset handling.
gitref:4a1a1bf3afc7[repository=src].
{{< sponsored "The FreeBSD Foundation" >}}

The `zfskeys` boot script no longer pauses boot to ask for an interactively entered ZFS passphrase unless both `zfskeys_enable` and `zfskeys_prompt_enable` are set to `YES` in man:rc.conf[5]. This restores the previous behavior of not prompting by default.
gitref:3f73758036c7[repository=src].

man:loader.efi[8] on a ZFS root under UEFI Secure Boot with man:mac_veriexec[4] enabled no longer reports a spurious no entry error. Users booting such a configuration should update the EFI loader and re-sign it.
gitref:6b1371fca772[repository=src].
{{< sponsored "Defenso" >}}

The lualoader adds `be-list` and `be-switch` commands so boot environments can be listed and switched directly from the loader command prompt, with matching man page updates.
gitref:f77062f506f7[repository=src].

The EFI boot loader no longer fails to boot in a situation where it previously jumped to the wrong code, fixing a load failure that could prevent booting on affected systems.
gitref:95632c90ba32[repository=src].
{{< sponsored "Netflix" >}}

The boot loader's graphics framebuffer code now batches updates through a shadow buffer instead of flushing on every operation, improving boot time on some platforms.
gitref:1802f2ca7215[repository=src].
{{< sponsored "The FreeBSD Foundation" >}}

The boot loader's Lua menu now follows symbolic links when locating bootable kernels, so symlinked kernel paths in /boot are detected and offered in the boot menu.
gitref:8c78774107a7[repository=src].

This section describes changes that affect networking in FreeBSD.

[[network-general]]
=== General Network

The resolver sortlist parser in libc is reimplemented, restoring the ability to configure address sorting via the sortlist directive. IPv4 and IPv6 addresses with optional masks or prefix lengths are accepted, and man:resolver[5] is updated accordingly.
gitref:55f219b3f766[repository=src].

A new sysctl tunable allows disabling kTLS receive offload independently of transmit offload, providing a mitigation for TLS receive path security issues.
gitref:4d3f5d2ca43c[repository=src].
{{< sponsored "Netflix; Chelsio Communications" >}}

rc.firewall now supports on-disk lists for `firewall_allowservices` and `firewall_trusted`: when a list element is an absolute path, the file is read and each non-comment, non-blank line's first word is treated as an address or subnet to add to the list.
gitref:3aec74070b0d[repository=src].

man:ifconfig[8] -v output now reports SR-IOV virtual function status for supported NICs. The display groups optional identity, initialization, resource, VLAN, administrator policy, protocol, traffic-permission, and fault-containment fields, while omitted values remain distinct from zero or false. Device-neutral PCI attachment and passthrough state remain available through man:iovctl[8] -L.
gitref:d36050dc99ea[repository=src].
{{< sponsored "Intel Corporation (initial version) | BBOX.io" >}}

The man:iflib[4] framework exports a per-device tx_watchdog_events counter at dev.<driver>.<unit>.iflib.tx_watchdog_events. The man:em[4], man:igb[4], and man:igc[4] drivers no longer count transmit watchdog resets as output errors, preventing those error counters from overstating packet loss.
gitref:f7ea2d561288[repository=src].
