The goal of this project is to improve OpenJDK support for FreeBSD/amd64 and FreeBSD/arm64.

Java is an important runtime environment for many high performance, critical enterprise systems.
Making sure Java based applications run correctly and efficiently on FreeBSD is important to ensure that FreeBSD will continue to be a viable and attractive platform for enterprises, as well as businesses and organizations of all sizes.

This quarter, a few rather big, invasive features have been merged upstream (link:https://openjdk.org/jeps/401[JEP 401: Value Objects] and link:https://openjdk.org/jeps/539[JEP 539: Strict Field Initialization]), meaning that it has been difficult to get reviews and acceptance for our changes in this period. We have spent the time on fixing issues with the BSD port, as well as keeping it up to date with the upstream changes as they have appeared.

The following fixes/improvements have been done in this quarter:

* Various fixes and enhancements
  - link:https://bugs.freebsd.org/bugzilla/show_bug.cgi?id=296945[Bug 296945]: The `wxneeded` ELF flag is now set on the JDK binaries, allowing java to run on systems with +W^X+ protection enabled.
  - link:https://bugs.freebsd.org/bugzilla/show_bug.cgi?id=294358[Bug 294358]: really build headless without installing Xorg libs
  - link:https://reviews.freebsd.org/D58841[Removed `USE_LDCONFIG` from OpenJDK 8 and 11 ports].
    Fixes link:https://bugs.freebsd.org/bugzilla/show_bug.cgi?id=297282[Bug 297282]: java/openjdk25 - libjava.so does not find libjvm.so
  - Only return symbols that match the requested address for `dladdr(3)` on BSD.
    This also reverts the default visibility of libjvm symbols back to hidden to avoid exposing internal symbols.
    This should also make the lib faster to load, and less resource hungry.
  - link:https://github.com/battleblow/jdk/pull/79[Fix debugd connect test on FreeBSD].
