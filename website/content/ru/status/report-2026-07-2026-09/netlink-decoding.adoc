=== Инфраструктура декодирования полезной нагрузки Netlink для инструментов трассировки FreeBSD

Ссылки: +
https://wiki.freebsd.org/SummerOfCode2026Projects/NetlinkPayloadDecodingInfrastructureForFreeBSDTracingTools[Страница проекта]

Контакт: Ishan Agrawal <ishan@freebsd.org>

Наставник: Kristof Provost <kp@freebsd.org>

PF использует Netlink для связи между инструментами пользовательского пространства и ядром, но до этой работы man:truss[1] не мог осмысленно декодировать полезную нагрузку сообщений PF Netlink и вместо этого отображал большую часть сообщения как необработанные данные.

Этот проект добавляет многоразовую инфраструктуру декодирования полезной нагрузки Netlink в `libsysdecode` и интегрирует её с man:truss[1], позволяя структурированно декодировать сообщения Netlink, а не раскрывать только их необработанное содержимое.

Ядром инфраструктуры является универсальный декодер атрибутов на основе таблиц декодеров.
Инфраструктура поддерживает декодирование различных типов атрибутов, включая целочисленные значения, строки, логические значения и вложенные атрибуты.
Затем команды Netlink могут предоставлять собственные таблицы декодеров, описывающие содержащиеся в них атрибуты, без необходимости отдельного механизма декодирования для каждой команды.

Инфраструктура была использована для добавления декодирования нескольких команд PF Netlink, включая `PFNL_CMD_KILLSTATES`, `PFNL_CMD_GETRULES` и `PFNL_CMD_GET_LIMIT`.

Например, сообщение PF Netlink, которое ранее отображалось в основном как непрозрачный буфер:

----
recvmsg(3,{0x90d83dda940,12,[{"@\^A\0\0\^P\0\^C\^C\^A\0\0\0\0\0"...,65536}],1,{},0,0},0) = 1060 (0x424)
----

С новой инфраструктурой декодирования man:truss[1] может декодировать сообщение Netlink и полезную нагрузку PF в осмысленные поля, например:

----
sendto(5,netlink{flags=NLM_F_REQUEST|NLM_F_ACK|NLM_F_ROOT|NLM_F_MATCH,seq=8,pid=0,len=92,type=18,pfctl={cmd=PFNL_CMD_GETSTATES{ifname=,proto=0,af=0,filter_addr=::,filter_mask=::,include_rule=FALSE}}},92,0,NULL,0) = 92 (0x5c)
----

man:truss[1] также был расширен для отслеживания протокола, связанного с сокетами `AF_NETLINK`, чтобы сообщения можно было передавать соответствующему декодеру.
Флаги сообщений Netlink декодируются как комбинации флагов `NLM_F_*`, при этом неизвестные биты сохраняются.

Работа в этом квартале заложила инфраструктуру, необходимую для продолжения добавления декодеров полезной нагрузки PF Netlink без дублирования логики разбора для каждой команды.
