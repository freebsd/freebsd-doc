=== Поддержка обнаружения splitlocks на x86

Контакт: Konstantin Belousov <kib@FreeBSD.org>

Большинство не-x86 платформ относительно строги в отношении правильного выравнивания типов данных.
С другой стороны, ISA x86 допускает любое выравнивание для операндов целочисленных скалярных операций.

Тем не менее, в регистре флагов процессора есть управляющий бит AC, который вызывает исключение выравнивания (fault) при невыровненных операциях.
Практически этот бит не слишком полезен, потому что большинство компиляторов генерируют код, который полагается на свободу невыровненного доступа на x86.

Особенно интересный случай невыровненного доступа — когда расположение операнда приводит к тому, что он охватывает две строки кэша (что невозможно для естественно выровненных данных).
Обычные (незаблокированные) операции вызывают так называемые torn reads и writes (рваные чтения и записи).
Этот эффект становится наблюдаемым начиная с микроархитектуры Intel Core2.

Ещё более интересный случай предоставляют заблокированные операции с использованием префикса LOCK в инструкции read-modify-write с невыровненными данными.
Чтобы удовлетворить гарантии ISA в этом случае, CPU должен либо захватить более одной строки кэша для эксклюзивного владения в протоколе когерентности кэша, подобном MESI, либо задействовать так называемую блокировку шины (bus lock), обеспечивающую глобальное владение кэшем.
Любой из вариантов имеет очень высокую стоимость и вызывает наблюдаемые вредные эффекты для других процессов и виртуальных машин, выполняющихся на том же физическом хосте.

Некоторое время назад Intel предоставил управление для операций блокировки, которым требуется охватывать более одной строки кэша (split locks).
Включение этого управления приводит к тому, что split locks генерируют то же исключение #AC, что и флаг AC, но только для split locks, а не для всех невыровненных доступов.

Эта функция управляется MSR платформы и является глобальной для каждого CPU, что исключает возможность сделать MSR напрямую доступным для пользовательского пространства.
Была разработана новая операция man:sysarch[2] I386_SET_SPLITLOCK, которая включает это управление для вызывающего потока.
Управление является частью машинного состояния, поддерживаемого при переключении контекста.

Цель — в основном помочь в отлове ошибок, когда создаются неправильно выровненные структуры блокировки, в отличие от Linux, который использует эту функцию для искусственного наказания таких процессов путём их замедления.
Если модификация кода программы невозможна, пользователи и администраторы могут через LD_PRELOAD загрузить тривиальный разделяемый объект, который включает это управление.
