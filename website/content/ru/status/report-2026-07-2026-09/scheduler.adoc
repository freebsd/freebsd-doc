[[_scheduler]]
=== Планировщик

Ссылки: +
link:https://wiki.freebsd.org/DevSummit/202609[Вики-страница DevSummit EuroBSDCon 2026] URL: https://wiki.freebsd.org/DevSummit/202609 +
link:https://wiki.freebsd.org/DevSummit/202609?action=AttachFile&do=view&target=EuroBSDCon2026-Scheduler.pdf[Слайды] URL: https://wiki.freebsd.org/DevSummit/202609?action=AttachFile&do=view&target=EuroBSDCon2026-Scheduler.pdf

Контакт: Olivier Certner <olce@FreeBSD.org> +
Контакт: Minsoo Choo <mchoo@FreeBSD.org>

В этом квартале в ULE и 4BSD был влит ряд исправлений и чисток:

- Исправлено смешение приоритетов потоков, ограниченных CPU, с разными значениями nice (4BSD).
- Исправлено слишком медленное снижение приоритета при потреблении CPU из-за некоторого устаревшего масштабирования SMP (4BSD).
- Исправлен выбор потока с наименьшим приоритетом на раннем этапе в некоторых краевых случаях (ULE).
- Локальные очереди выполнения (используемые для привязанных/прикреплённых потоков) теперь выделяются только для фактически присутствующих CPU (4BSD).
- Удалены неиспользуемые `hlt_cpus_mask` и `sched_do_timer_acccounting()`.
- Удалён неиспользуемый `kern.sched.4bsd.followon` (4BSD).
- При установке `kern.sched.{4bsd,ule}.slice` проверяется, что значение имеет смысл, и обеспечивается обновление зависимых внутренних констант, таких как `hogticks` и `sched_slice_min`.
- Обеспечено, что `sched_slice_min` и вычисление кванта остаются разумными для малых значений кванта (ULE).
- Обновлены некоторые комментарии.

Работа продолжается и близится к завершению по очистке механизма, позволяющего нескольким реализациям планировщика (так называемым «экземплярам») сосуществовать в одном ядре.
Из единого списка дескрипторов функций он теперь автоматически порождает объявление функций в интерфейсе планировщика и в экземплярах планировщика, поля структуры дескриптора экземпляра планировщика и функции диспетчеризации.
Готовится второй раунд изменений с целью потенциально удалить пространства имён функций реализации (например, наличие `ule` или `4bsd` в их именах) в исходном коде, фактически переименовав их обратно в их старые имена, которые являются именами интерфейсных функций, сохраняя при этом пространства имён для символов C, что требуется для отладки и в целом для манипуляций различными инструментами ELF.

В фоновом режиме продолжается работа над решениями давних недостатков планировщика ULE, таких как несправедливость для неинтерактивных потоков в некоторых особых обстоятельствах и очень слабый эффект значений nice.
Для получения дополнительной информации обратитесь к link:../report-2026-01-2026-03/#_scheduler[предыдущему отчёту] и link:https://wiki.freebsd.org/DevSummit/202609?action=AttachFile&do=view&target=EuroBSDCon2026-Scheduler.pdf[слайдам] последней презентации на link:https://wiki.freebsd.org/DevSummit/202609[DevSummit EuroBSDCon 2026].
