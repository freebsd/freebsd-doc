=== NFS через Remote Direct Memory Access (RDMA)

link:https://github.com/viniciusferrao/freebsd-src.git[Актуальные исходники NFS-сервера в ветке freebsd-rdma] URL: link:https://github.com/viniciusferrao/freebsd-src.git[]
link:https://people.freebsd.org/~rmacklem/nfs-over-rdma-setup.txt[nfs-over-rdma-setup.txt] URL: link:https://people.freebsd.org/~rmacklem/nfs-over-rdma-setup.txt[]

Контакт: Rick Macklem <rmacklem@freebsd.org>, Vinicius Ferrao <ferrao@versatushpc.com.br>

В настоящее время NFS в FreeBSD поддерживается через TCP (и UDP для NFSv3).
Этот проект добавляет поддержку NFS через RDMA, как описано в RFC-8166 и RFC-8267.
Это должно позволить RDMA-совместимым сетевым картам разгрузить большую часть сетевого транспорта и повысить производительность в быстрых локальных сетях.

Благодаря Vinicius был достигнут значительный прогресс.
У него работает серверная сторона NFS, и, насколько я знаю, довольно хорошо.

Клиентская сторона теперь довольно хорошо тестируется против сервера Vinicius, и как клиент, и сервер готовы к тестированию третьими сторонами.
Для тестирования требуются клиент и сервер с сетевыми картами Mellanox ConnectX4->6, работающие на ядре, собранном из недавних исходников FreeBSD main.

Информацию о настройке тестовой среды см. в [.filename]#nfs-over-rdma-setup.txt#.

Ядра stable/15 должно быть достаточно для загружаемых модулей через несколько недель.
Клиентский код также должен быть закоммичен в FreeBSD main через несколько недель, с MFC в stable/15 к концу 2026 года.
Серверный код был создан с помощью генеративного ИИ, и проект FreeBSD работает над политикой обработки материалов, созданных генеративным ИИ.
Тем временем серверный код будет доступен как "неофициальный порт", собирающий загружаемый модуль ядра.

Мы были бы очень признательны тестированию третьими сторонами.

Спасибо Vinicius за работу над NFS-сервером и участникам кластера FreeBSD Netperf, без которых я бы никогда не протестировал этот код.
